# 紫微接入方案（评估与规划）

> 创建：2026-11-10　状态：评估完成，待定接口形态
>
> 目标：**用我们自己做的前端，复用已有 ziwei 项目的排盘算法与知识库**，不采用它自带的 Next.js 界面。

## 一、结论

**技术完全可行。** 现有 ziwei 项目的排盘内核本来就是纯前端 TypeScript，不依赖后端，天然可以脱离它自己的界面单独使用。

关键证据（均在 `/Users/lhr/EnMo/ziwei`，GitHub：`Renhuai123/ziwei-doushu`）：

| 证据 | 说明 |
|---|---|
| `app/chart/page.tsx:7` | 直接 `import { generateChart }`，提交表单即在浏览器内算完，无任何 API 调用 |
| `lib/ziwei/algorithm.ts:453` | `generateChart(birthInfo)` 输入 `BirthInfo`，输出纯 JSON `ZiweiChart`，不碰 Node / 数据库 |
| `next.config.js` | `output: 'export'` 静态导出，说明整套已能纯静态运行 |
| 依赖 | 仅 `iztro` + `lunar-javascript`；现有构建中引擎相关 chunk 约 808KB（gzip ≈ 252KB），纯引擎单打包更小 |
| README「七、开源边界」 | 界面只是 Demo，排盘内核明确允许二次开发 |

## 二、能复用 vs 要重写

| 类别 | 内容 |
|---|---|
| ✅ 直接复用（`lib/ziwei/*`） | 安星算法、四化、星曜亮度表、闰月/晚子时口径、真太阳时、大限/流年、格局识别 `patterns.ts`、十二神煞、古籍原文 `lib/classics`、`lib/nihai`、`heming-knowledge` |
| 🔧 需要重写（我们自己做） | `components/ChartBoard.tsx`、`PalaceCell.tsx` 等界面——十二宫 4×4 网格、三方四正连线、四化高亮、解读面板。React 组件不能直接进纯静态站，但布局逻辑（地支→网格坐标映射）可照搬思路 |
| ⚠️ 拿不到 | 线上断语库、AI 解读 prompt、后端 API、用户/支付系统（详见第三节） |

## 三、三个必须知道的限制

### 3.1 「知识库」分两层，真正断语库不开源

- **开源**：格局库、古籍公版原文、四化、倪海厦知识、SEO 知识图谱。
- **不开源**：线上上万行的 13 主题「断语库」（`lib/ziwei/db-analysis.ts` 是空占位）、AI 解读 prompt、后端 API、用户系统。
- **替代方案**：官方 **v4.0 数据集（CC BY 4.0，可商用）**——67.5 万盘 × 13 维预生成解读，压缩约 161MB / 解压 56.6GB，按年份 77 个文件。静态站无法全量打包，需按需取用（后端 / 对象存储）。

### 3.2 要做「AI 解读 / 长文断语」→ 必须有小后端

纯静态前端不能安全放 API Key。需 EdgeOne Pages Functions 或香港轻量后端（域名记录里已预留 `api.haoran.lu` 方案）。不加后端则只能做「排盘 + 格局 + 古籍引用」，不能做长文断语。

### 3.3 站点气质会变重

当前站是「零构建、单文件、极简星空」。建议紫微放独立路由（如 `/ziwei/` 或 `ziwei.html`），首页保持原样。

## 四、推荐接入方式

把 `lib/ziwei` + `iztro` + `lunar-javascript` 用 **esbuild 打成单文件 IIFE**（如 `ziwei.engine.js`，暴露 `window.generateChart`），一次性构建后产物提交仓库。

- 好处：网站运行时**依然零框架、零构建**，紫微页面 `<script src>` 引入即可。
- 注意：`lib/ziwei/patterns.ts:21` 有 `import 'server-only'`，打包时需移除。

## 五、分阶段计划

1. **Phase 1（核心）**：引擎 bundle + 自绘十二宫本命盘（含亮度、四化、命宫/身宫）。中等工作量。
2. **Phase 2**：大限 / 流年切换、三方四正、格局 `patterns`、古籍引用。
3. **Phase 3（可选）**：解读——接 v4.0 数据集（需后端 / 存储）或自建 LLM 解读（需 API 后端）。

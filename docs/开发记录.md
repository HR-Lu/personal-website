## 一、项目定位

个人站，先做好「气质」，再往上加内容。当前阶段只做背景，不铺板块。

| 约束 | 结论 |
|---|---|
| 域名 | haoran.lu（.lu 后缀，工信部未批复） |
| ICP 备案 | **不可备案**，只能用境外节点 |

| 断点 | 字号 | 位置 |
|---|---|---|
| ≥1025px | `clamp(40px, 5.6vw, 78px)` | left `clamp(22px, 9.5vw, 160px)`，top 38.2% |
| 641–1024px | `clamp(56px, 8vw, 80px)` | 同上 |

## 三、背景效果：来源与实现

### 3.1 来源

不是凭感觉画的，是从 mos.caldis.me 的编译产物里逆向出来的 canvas 组件：

- 页面结构：`<div class="fixed inset-0 -z-10 overflow-hidden">` → 一层灰色径向柔光 + 一个全屏 `<canvas>`
- 组件内部：`getContext('2d', {alpha:true})`，三组白色线条，`globalCompositeOperation = 'lighter'` 画线、`'destination-out'` 逐帧擦除留拖尾

### 3.2 运动参数（与 mos 原版一致）

| 参数 | 值 | 含义 |
|---|---|---|
| densityDesktop / densityCoarse | 2 / 1 | 每 5000px² 粒子数 |
| countMin / countMax | 800 / 2000 | 粒子总数上下限 |
| damping | .83 | 每帧保留的速度比例 |
| accel | 1.15 | 流场转向加速度 |
| speedBase | .2 | 位移倍率 |
| fieldScaleX / Y / XY | .003 / .002 / .001 | 三层流场频率 |
| angleMul | .1 | 流场值 → 转向角（×π） |
| timeX / timeY / timeXY | 0 / .00015 / .00035 | 流场随时间演化速度 |
| influenceR | 490 | 鼠标漩涡半径（px） |
| swirl | 3 | 漩涡强度 |
| fade | .115 | 每帧擦除拖尾比例 |
| lineWidth | 1.25 | 轨迹线宽 |

运动公式（原样照抄）：

```
angle = (sin(x*fieldScaleX + (seed+t)*timeX)
       + cos(y*fieldScaleY - (seed-t)*timeY)
       + sin((x+y)*fieldScaleXY + (seed+t)*timeXY)) / 3 * π * angleMul

vx = vx*damping + cos(angle)*accel
vy = vy*damping + sin(angle)*accel

鼠标：d < influenceR 时
   vx += -dy/d * (1 - d/influenceR) * swirl
   vy +=  dx/d * (1 - d/influenceR) * swirl

p += v * speedBase * (dt/16)
```

粒子位置用伪随机 `fract(10000*sin(x))`，出界后按 `seed + 0.001*now` 重新投放。

### 3.3 视觉一致性

当前版本**严格对齐 mos 原站**：纯黑底、三档白色线条（.50/.43/.36）、`lighter` 发光、`destination-out` 擦除拖尾，无任何额外配色或装饰层。

试过但已全部回退的方向：黑洞暖色配色、CSS 吸积盘 / 黑洞叠加层、白天静态大图 + 昼夜切换按钮。原因：都不如原版干净耐看。

## 四、性能

粒子渲染每个粒子只做两件事：推一次速度、画一条 1~2px 线段。真正的开销是全屏像素填充（擦除 + 发光混合）。

已做的优化：

| 优化 | 说明 |
|---|---|
| 同色线段合并 | 800 次 `stroke` 合并成 3 条 Path，视觉不变 |
| DPR 上限 2 | Retina 下填充像素最多 4 倍，不随 3x 屏继续放大 |
| 页面隐藏即停 rAF | 不后台烧 CPU / GPU |
| 辉光贴图预渲染 | 不在每帧创建 radialGradient |
| 尺寸变化防抖 | resize 后 150ms 才重建粒子 |
| prefers-reduced-motion | 直接不渲染 canvas |

参考量级：1440×900@2x ≈ 520 万像素/帧。现代独显/M 系轻松 60fps；老核显可能 30~40fps，那时降 `countMax` 即可。

### 为什么不引入 Vue

Vue 管 DOM 与状态（模板编译、响应式、虚拟 DOM diff），对 canvas 的每帧绘制没有任何帮助，还会多 30~40KB 运行时。纯静态页在本项目的收益是**加载速度**和**零维护**，不是开发体验。等站点变成多页面、多板块、有大量 UI 状态时再考虑框架。

## 五、已废弃的方案

| 方案 | 状态 | 原因 |
|---|---|---|
| 文字碰撞（粒子撞字形反弹 + 撞击火花） | **已删除** | 实现用「离屏字形遮罩 + 梯度法线」做反射，遮罩与 DOM 文字有约 6px 偏差，实际观感不好，用户要求去掉 |

如果以后还想做，改进方向：改用逐元素矩形（`getClientRects`）而不是字形遮罩，或者接受"粒子穿过文字、只在文字上方叠一层 blend 光晕"的取巧做法。

## 六、文字设计规范（借鉴 mos）

mos 的高级感来自三点，后续所有文字都按这个来：

1. **字体分工**
   - 展示标题：无衬线几何体（mos 用 Syne），字重 600~700
   - 正文：Space Grotesk / 系统无衬线
   - 标签、日期、编号：等宽（IBM Plex Mono）
2. **色板**（mos 后台 token）
   - 底色 `#000` / 近黑 `#090909`
   - 主文字 `#ffffff`（约 92%）、次级 72%、弱化 52%
   - 强调色 `#2EC8B0`（青绿），只在标签、链接、状态上用
3. **排版**
   - 标题大、行距紧、留白多；正文行高 1.8~2
   - 小标签用等宽 + 大字距（.2em~.35em），前面加 `//` 之类的符号
   - 卡片：1px 白色 10% 描边 + 半透明深底 + backdrop-blur

中文需要注意：无衬线标题走 `PingFang SC / Noto Sans SC`，衬线标题走 `Songti SC / Noto Serif SC`，字距 .1em~.15em 才不会散。

### 9.5 LLM 接入：中转站 + 模型降级（2026-11-10）

- LLM 走中转站（OpenAI 兼容协议），**不走官方 API**——顺带绕开了香港 IP 被官方拒绝的限制
- 站内模型：`deepseek-v4-pro` / `deepseek-v4-flash` / `deepseek-v4.1-flash`（思考型，delta 先吐 `reasoning_content` 再吐 `content`，前端只渲染 content）
- **当前 env 优先级（2026-11-11 复查）**：`deepseek-v4.1-flash,deepseek-v4-flash,deepseek-v4-pro`——flash 打头，先保出字速度，失败再往上升级

- 已实测：假模型放首位时自动落到 flash 正常完成解读；正常时 pro 生效（约 1600 tokens/次）
- 防护与限制：每 IP 每分钟 8 次、chart ≤ 60KB、max_tokens 4096、CORS 仅 haoran.lu

### 9.7 追问与限流修正（2026-11-10）

- **追问（history）**：`POST /api/interpret` 新增可选 `question`（≤500 字）与 `history`（≤12 条 user/assistant，每条 ≤4000 字符）。首轮只发 chart；追问轮 chart 仍作首条 user 消息（后端无状态），history 依次拼接、最新问题只追加一次（修掉了旧版把 question 同时嵌进 chart 消息又追加一次的重复）。追问轮 system prompt 附加指令：直接回答问题、不重复完整结构化解读。香蕉记忆测试通过
- **前端配套**：解读入列前截断到 3800 字符（防后端 400），history 本地留最近 14 条、发送时取末 12 条
- **限流修正**：原版 `request.client.host` 经 Caddy 反代后恒为 127.0.0.1，等于**全站共享一个 8 次/分钟桶**。现在仅当对端是回环时才取 `X-Forwarded-For` 首跳作为限流键
- **XFF 防伪**：Caddy 默认是**追加**而非覆盖访客自带的 X-Forwarded-For，伪造首跳即可绕限流。Caddyfile 的 reverse_proxy 加 `header_up X-Forwarded-For {remote_host}` 强制覆盖为真实连接 IP
- **CORS**：env 的 `ALLOWED_ORIGINS` 增加 `http://localhost:8000,http://127.0.0.1:8000`（本地联调用）；后又加 `ALLOWED_ORIGIN_REGEX` 放行本机/局域网任意端口（`localhost|127.0.0.1|192.168.x.x`），手机连局域网 IP 调试可用。注意：**file:// 双击打开页面永远不行**（Origin 为 null，Safari 报 "Load failed"），必须经 http 服务访问；null 也刻意不放行（沙箱 iframe 伪造可刷 LLM key）
- 中途 SSH 一度被服务器拒（认证后立刻断开，疑似 sshd 限流），几分钟后自愈，未改服务器配置

### 10.3 AI 解读与追问

- **首轮也走追问通道**：原本首轮只发 `{chart}`，后端会走「完整结构化解读」的长 system prompt，实测首字 45–73s、正文 960–1050 字（20 行小作文）。现改为 `payload.question = FIRST_INSTRUCTION`，把格式约束塞进 question：
  - 四段「性格 / 事业 / 感情 / 提醒」，每段 1–2 句，每段末括号注明依据（宫位 + 星曜 + 四化），全文 ≤220 字
  - 明确要求「不要思考过程、不要开场白、不要总结段、不要免责声明」
  - 追问追加 `FOLLOW_SUFFIX`（≤200 字、直接给结论），防止模型又铺开写
  - 实测收益：正文 200–270 字、总时长 17–48s（首次 45s 左右，之后 17–20s，模型侧思考仍占大头）
- **等待反馈**：`reasoning_content` 不再丢弃，按 `WAIT_STEPS` 分三段文案（正在推演命盘 → 星曜与四化已就位 → 正在逐宫推演），并累计思考字数显示「（已推演 N 字）」，替代原来直白跳秒数的「正在推演… Ns」
- **输出清洗** `cleanOutput()`：滤掉免责声明行、空行、≤30 字的「好的/以下是/根据您提供的命盘」开场
- **排版**：`mdToHtml()` 把段首 `性格/事业/感情/提醒`（带不带 `**` 都行）统一渲染成 `<b class="md-k">`，加粗 + 0.14em 字距 + 9px 右间距，段间单空行；极简 markdown（标题/加粗/列表）+ 闪烁光标，滚动条跟随到底
- 追问：输入框（≤200 字）+ 发送，带最近 history；用户问题为浅底气泡（2026-11-11 去掉 `// 你` 前缀）；流式中禁用输入
- 错误路径：HTTP 非 200 读 detail、流内 `error` 事件、空回复兜底文案，均红字内联显示不清空已有内容
- 底部声明「内容由模型生成，仅供参考」已于 2026-11-11 移除，AI 区只留输入框与发送
- 后端参数（`model` / `thinking` / `reasoning_effort` / `max_tokens`）实测均被服务端忽略，前端无法进一步提速；真正的加速只能改 `/opt/ziwei-api/app.py` 的模型优先级与 prompt

### 10.5 果冻按钮（入口按钮，2026-11-10，v3 整体弹簧·松绑）

演变：v1 软体边缘形变（质点弹簧）→ 用户要的是**整体动**；v2 整体弹簧+绳长脱扣（拉到 26px 猛弹回）→ 用户嫌弹得太凶，要**鼠标离开才弹回**；v3 定稿：

- **结构**：外层 `<button>` = 静态命中区（cursor:none 藏光标）；内层 `.zw-jelly-body` = 视觉整体（CSS 圆角半透明块 + 白字同标题），transform 位移
- **物理**：刚体二阶弹簧（ω=17rad/s≈2.7Hz，半隐式欧拉）。**目标 = 光标相对按钮中心的位置 × 0.30，欧氏钳制 26px**——光标在按钮里 → 方块朝光标方向被拖着倾斜；光标回中心 → 方块归位（对称可预期，比 v2 的累计位移模型直觉）；光标离开 → 目标归零 + 欠阻尼（ζ=0.16）晃 3~5 个来回回原位
- **停表条件 = 相对目标静止**（悬停停在倾斜位也停表，新交互 pointermove 重启 rAF），修掉了光标停住后 rAF 空转的低效；停表不清 transform（防倾斜稳态瞬移）
- 触屏（pointerType≠mouse）不启用物理走原生点击；reduced-motion / JS 失效回退纯 CSS
- node 仿真 8 组场景（朝光标倾斜/钳制/对称归位/左右对称/松手过零晃动收敛/斜向欧氏/极端稳定/未 hover 无效/停表）全过。v1/v2 保留在 git 历史

## 十一、非 PC（触屏）适配（2026-11-11）

手机/平板没有鼠标，原来的光标跟随与悬停逻辑反而是负担，逐项按手指用法调整：

- **粒子不再跟手势**：`pointermove` 只在 `(hover: hover) and (pointer: fine)` 成立时挂载（`hasCursor`）。触屏拖动页面时不会再把流场搅乱，粒子完全靠自身流场一直飘；`blur` 复位也只挂在有鼠标的设备上。视觉参数（速度、密度、拖尾）不变，触屏仍是 `densityCoarse: 1` 的稀一点版本
- **iOS 输入框自动放大**：Safari 聚焦字号 <16px 的输入框会把整页放大，而浮层不可滚动、放大后很难退回。触屏下 `.zw-input / .zw-select / .zw-ai-bar input` 统一 16px（placeholder 14px）
- **点按反馈**：交互元素统一 `touch-action: manipulation` + `-webkit-tap-highlight-color: transparent`，去掉点按灰块与双击缩放延迟；点按不再触发 `.zw-go` 的悬停位移/发光
- **长按选中**：宫格、中央卡、label 加 `user-select: none`，避免长按弹出选字/复制；AI 解读正文仍可选中
- **安全区**：浮层内边距按 `env(safe-area-inset-*)` 让出底部横条与刘海，关闭按钮顶到 `calc(14px + inset-top)`
- **下拉刷新**：`body { overscroll-behavior-y: none }`，避免在浮层里下滑把页面刷掉
- **键盘回车语义**：称呼 `enterkeyhint="done"`、追问输入框 `enterkeyhint="send"`，手机回车键显示对应动作

二次精进（2026-11-11，同一轮）：

- **点按涟漪**：触屏 `pointerdown` 记录 `{x,y,t0}`（最多并存 3 个），在半径 150px 内给一个切向推力，900ms 线性衰减；过期的脉冲每帧统一清理一次，不参与粒子内循环。手指点一下，粒子在落点旋开一圈就散，不影响整体流场。桌面（有鼠标）不挂这个监听
- **键盘让位**：`visualViewport` 的 `resize/scroll` 里算「键盘占高」，写进 `--zw-kb`（上限视图 60%），触屏下 `.zw-overlay` 用 `height: calc(100% - var(--zw-kb))` 收缩到键盘上方，追问输入框不再被盖住；键盘收起自动恢复
- **追问快捷问题**：AI 输入框上方一排胶囊「今年的感情 / 事业方向 / 要注意什么」，首轮解读完成后才出现、流式中隐藏，点一下直接发送。手机上免打字，桌面也能用
- **触屏省电**：DPR 上限 2 → 1.5（填充率约少 44%，肉眼几乎无差）。**没有做 45fps 限制**——60Hz 屏幕上按 45 截帧只会变成 16/33ms 交替的 30fps，卡顿比省电更明显；要再省就只能降粒子数，那会改变 mos 原版密度，按硬约束不动
- 回归：960px 与 390px 宽度下均无横向溢出，控制台 0 报错

### 11.1 手机端改为整页滚动（2026-11-11）

问题：原来手机也锁一屏，命盘占上部、解读区只有一条窄缝、内部单独滚动，看解读时可视范围很小。

- **整页一起滚**：≤860px 时 `.zw-overlay` 改 `display:block; overflow-y:auto`，`.zw-panel` 改 `height:auto; min-height:100%`，解读区 `.zw-ai-log` 取消内部滚动（`overflow:visible`），正文按内容自然撑开；手指一滑，命盘、解读、输入框整体上移
- **命盘给固定高度**：`height: clamp(300px, 54vh, 430px)`（矮屏 `clamp(260px, 48vh, 380px)`），字号继续走 `cqh` 等比缩放；空出来的高度全部让给解读正文
- **滚动容器跟着变**：JS `scroller()` 在窄屏返回浮层本身、桌面返回解读区；`scrollLog` 的「是否在底部」判断同步切到对应容器，自动跟随不失效
- **新回答定位**：窄屏下新气泡 `scrollIntoView({block:'start'})` + `scroll-margin-top:64px`，回答从顶部开始读，不顶到关闭按钮下面；桌面仍滚到底部
- 进入表单 / 排盘时 `overlay.scrollTop = 0`，切换视图不会停在上一次的滚动位置
- 实测（iframe 390×844 模拟）：`overlay.scrollHeight 2322 / clientHeight 844` 可滚，解读区 `scrollHeight === clientHeight`（无内部滚动条），命盘高度 430，无横向溢出
